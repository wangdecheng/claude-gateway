# 下游客户端负责模型请求重试

对于模型请求，上游返回非成功 HTTP 响应时，网关不进行内部重试，由下游客户端作为唯一重试责任方。网关保留上游状态码和响应体，并转发 `Content-Type`、`Retry-After` 及上游请求追踪标识；连接级、传输级和敏感响应头不属于透传契约。这样可以保留客户端基于原始上游错误制定的重试策略，并避免网关重试与客户端重试叠加造成请求放大。

响应流开始后，上游发出的合法 SSE 错误事件保持原样；连接中断、超时或协议故障直接中断下游流，不合成正常的消息结束序列。下游因此能够区分正常完成、上游明确报错和流式传输失败。

透传仅适用于网关实际收到的上游模型错误响应。认证、余额、路由、配置和请求校验等网关自身错误继续使用网关错误契约；尚未收到上游响应的连接或超时故障也由网关表述，不伪装成上游响应。上游 `401/403` 视为 Provider 凭据或配置故障，转换为网关 `502`，避免误导客户端检查自己的网关凭据或泄露内部 Provider 信息。

失败请求只结算上游在失败前明确报告的用量。上游未报告用量时不创建待结算记录，也不使用本地估算值对失败请求计费。

该契约适用于 `/v1/messages` 的所有上游 Provider，并由共享传输边界统一实施；不按模型或 Provider 添加例外。

网关在收到上游响应前发生 DNS、连接、TLS 或协议故障时返回 `502`，等待上游响应头超时时返回 `504`；两者使用网关定义的 Anthropic 兼容 `api_error`，且不在网关内重试。
